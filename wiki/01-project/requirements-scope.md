## How to complete this page

Write in English. Replace prompts with actual findings; keep unresolved questions visible. Use short paragraphs, tables and diagrams only when they improve understanding. Label evidence, assumptions and proposals separately.

## Functional requirements

**Required work:** Give each requirement a stable ID and state the user outcome, not a framework choice.

**Expected output / writing format:** Requirement ID / description / rationale / acceptance concept.

**Working content:** _To be developed by the owner and contributors._

## Quality requirements

**Required work:** Discuss reliability, security, usability, traceability and operating constraints; avoid unsupported targets.

**Expected output / writing format:** Quality attribute / target or TBD / verification approach.

**Working content:** _To be developed by the owner and contributors._

## MVP & exclusions

**Required work:** Identify proposed minimum demonstrable scope and what is deferred; obtain PO agreement.

**Expected output / writing format:** Capability / in or out / rationale / status.

**Working content:** _To be developed by the owner and contributors._

## Assumptions & dependencies

**Required work:** Surface domain assumptions, data availability and external runtime constraints.

**Expected output / writing format:** Assumption / risk / owner / question link.

**Working content:** _To be developed by the owner and contributors._
