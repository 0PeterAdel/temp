> **Objective:** Translate design into work packages and Jira work items with clear traceability.

## How to complete this page

Write in English. Replace prompts with actual findings; keep unresolved questions visible. Use short paragraphs, tables and diagrams only when they improve understanding. Label evidence, assumptions and proposals separately.

## Work packages

**Required work:** Split agreed design outcomes by deliverable and dependency, not automatically by layer.

**Expected output / writing format:** Package ID / design link / expected deliverable / owner role / dependencies.

**Working content:** _To be developed by the owner and contributors._

## Jira item design

**Required work:** Choose Epic, Story, Task, Subtask, Bug or research spike by scope; link requirement and design baseline.

**Expected output / writing format:** Item type / summary / acceptance criteria / dependency / design reference.

**Working content:** _To be developed by the owner and contributors._

## Handoff & tracking

**Required work:** Link Jira as work-status source of truth; keep design rationale and work breakdown map here.

**Expected output / writing format:** Package / Jira key / design version / evidence link.

**Working content:** _To be developed by the owner and contributors._

## Review checklist

- [ ] All required outputs above are present or explicitly marked not applicable with a reason.
- [ ] Claims are supported; proposed material and unknowns are marked.
- [ ] A different person reviews the page, including relevant domain specialists if needed.
- [ ] Links to impacted design, research and decisions are current.
